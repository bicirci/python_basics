# 浅拷贝与深拷贝实验观察

## 数据结构说明
使用列表 `a = [1, [2, 3], (4, 5)]`，其中：
- 顶层元素：`a[0]` 为整数（不可变）
- 嵌套可变对象：`a[1]` 为列表（可变）
- 嵌套不可变对象：`a[2]` 为元组（不可变，修改时整体替换）

对四种方式分别测试：
1. 直接赋值 `b = a`
2. 列表自带的浅拷贝 `b = a.copy()`
3. `copy.copy(a)` 浅拷贝
4. `copy.deepcopy(a)` 深拷贝

依次执行三种修改操作（均作用在原对象 `a` 上）：
- 修改顶层：`a[0] = 10`
- 修改嵌套可变：`a[1][0] = 20`
- 修改嵌套不可变：`a[2] = (6, 7)` （重新绑定引用）

---

## 关键观察与解释

### 1. 直接赋值 `b = a`
- `b` 和 `a` 指向**同一个对象**（`id(a) == id(b)`）。
- 无论修改顶层、可变嵌套还是替换不可变嵌套，`b` 都会同步变化，因为二者是同一容器的别名。
- 内部所有元素的 `id` 也完全相同，修改本质是改变同一内存区域的内容。

**结论**：直接赋值不产生任何拷贝，仅仅是引用绑定。

---

### 2. 浅拷贝 `b = a.copy()` 和 `copy.copy(a)`
二者行为完全一致（都是浅拷贝），以下统称“浅拷贝”。

- **初始状态**：`a` 和 `b` 的外层容器 `id` 不同（复制了新列表），但内部元素 `a[1]`（列表）和 `a[2]`（元组）的 `id` 完全相同——说明浅拷贝**仅复制外层容器，内部元素仍然是原对象的引用**。

- **修改顶层元素** `a[0] = 10`：  
  `a[0]` 指向了新的整数对象，`b[0]` 仍指向原来的整数 `1`。  
  `a` 和 `b` 的 `id` 不变，但各自顶层元素独立，互不影响。

- **修改嵌套可变对象** `a[1][0] = 20`：  
  因为 `a[1]` 和 `b[1]` 引用的是**同一个列表对象**（`id` 相同），修改该列表的内容会同时影响 `a` 和 `b`。  
  这是浅拷贝最典型的特征：**共享内部可变对象**。

- **修改嵌套不可变对象** `a[2] = (6, 7)`：  
  元组本身不可变，此处是重新绑定 `a[2]` 指向一个新的元组对象，`a[2]` 的 `id` 改变，但 `b[2]` 仍指向原来的元组 `(4,5)`（`id` 不变）。  
  因为元组不可变，所以“修改”实质是替换引用，而浅拷贝复制的是原引用，故不受影响。

**核心结论**：浅拷贝创建了新的外层容器，但内部元素的引用与原对象相同，因此**对内部可变对象的修改会共享**，对顶层元素或不可变元素的重新赋值则各自独立。

---

### 3. 深拷贝 `b = copy.deepcopy(a)`
- `a` 和 `b` 的外层容器 `id` 不同，且内部所有层级的对象都被递归复制。
- 无论是修改顶层、修改嵌套可变列表，还是替换嵌套元组，`b` 都完全不受影响，因为 `b` 拥有独立的内存副本。
- 从 `id` 可见，`a[1]` 和 `b[1]` 的 `id` 不同，`a[2]` 和 `b[2]` 的 `id` 也不同（即使元组不可变，深拷贝也会复制一份新元组）。

**结论**：深拷贝完全独立于原对象，修改原对象不会影响拷贝。

---

## 总结
- **直接赋值**：无拷贝，完全共享。
- **浅拷贝**（`.copy()` / `copy.copy()`）：复制外层容器，**内部可变对象共享，不可变对象共享但不可修改**（重新赋值不影响拷贝）。
- **深拷贝**（`copy.deepcopy()`）：递归复制所有层级，完全独立。

本次实验通过 `id()` 追踪对象内存地址，清晰证实了浅拷贝“复制外层，共享内部可变”的特性，这是区分浅拷贝与深拷贝的本质所在。


仅包含不可变对象的元组，deepcopy() 可以复用原对象。深拷贝的语义重点是解除需要解除的可变共享，不保证每个对象的 id 都不同
